# rclona

基于 [rclone](https://rclone.org) 的中文网盘备份面板：把一个网盘（源）定时**镜像备份**到另一个网盘（目标），
备份失败时用大白话告诉你卡在哪一步、是什么原因，还会通过 Telegram 通知你。

不懂编程也能用：一个 Docker 容器、一个配置文件、一个网页，齐活。

## 它能做什么

- **定时镜像备份**：每天 / 每周（可多选星期）/ 每月 / 每隔几小时 / 每隔几天，也支持高级的 cron 表达式；源网盘和目标网盘保持一模一样（纯镜像 + 校验和比对，文件内容变了能发现）
- **三种同步方式**（建任务时选，默认镜像）：镜像 = 目标与源完全一致；单向增加 = 只往目标添新文件、源里删了目标也不删；双向同步 = 两个网盘互相对齐，同一个文件两边都改过时新版本赢、旧版本改名留一份副本不丢，并有防误删刹车
- **一个任务多组文件夹**：一个任务里可以配多组「源文件夹 → 目标文件夹」一起跑，一组出问题不影响其他组
- **数据安全选项**（建任务时按需开，老习惯默认全关）：被改/被删的文件先留一份旧版本存档（可设保留天数）、一次要删太多自动停下报警、正式跑之前先「试运行预览」、每次跑完有变更明细（加了/改了/删了哪些）、同步限速、文件改名识别不重传、备份加密（文件加密后再存进目标网盘）
- **失败说人话**：每次备份分成 5 个阶段（连接源网盘 → 扫描比对 → 连接目标网盘 → 传输文件 → 校验），失败时明确指出卡在哪一步、原因是什么（密码错了 / 连接不上 / 空间不足……），不用看英文日志猜
- **Telegram 通知**：备份失败、网盘连接失效（以及恢复正常）时，通过 Telegram 机器人第一时间告诉你；填好「面板访问地址」后，通知末尾还会带一条链接，点一下直达出错的那条记录
- **网盘连通自检**：每天凌晨 3 点自动检查每个网盘还能不能连上；连不上会每 5 分钟重试，连续 3 次失败判定失效并发 Telegram 通知，恢复后自动解除并再通知一声
- **多网盘支持**：Cloudflare R2、Koofr、WebDAV、各类 S3 存储、本地目录等（由 rclone 驱动，添加时填几个参数即可，每个参数都有中文说明和「去哪找」的提示）
- **网盘详情页**：点任意网盘（网盘页或左侧边栏整行都能点）就能看它的连接状态、容量、它在给谁备份 / 被谁备份、最近的运行记录
- **网盘可暂停**：暂时不用的网盘可以暂停（不参加自检、相关任务自动跳过），侧边栏状态点变灰，一眼能分清
- **能备份服务器文件**：开启只读挂载后，这台服务器上的重要目录也能当作「本地网盘」，定时备份到其他网盘（见「四、备份服务器上的文件」）
- **失败可对账**：失败记录可以「标记已处理」，处理过的记录会变绿并注明时间，历史不丢、心里有数

> ⚠️ **先看这一条**：默认的备份方式是「镜像」——目标网盘会被改得和源网盘**完全一致**。
> 源里删掉的文件，目标里也会被删掉；目标里多出来的文件，也会被清掉。请勿把目标选成也在日常使用的目录。
> （建任务时也可以改选「单向增加」或「双向同步」，那就不按这条来了；第一次用双向同步建议先拿个小文件夹试。）

## 一、准备工作

你需要一台能长期开机的设备，任选其一：

- 一台云服务器（VPS），或
- 一台 NAS（群晖、威联通、极空间等支持 Docker 的型号），或
- 家里的一台小主机 / 树莓派

并且上面已经装好了 **Docker** 和 **Docker Compose**（v2）。检查方法，在服务器终端里运行：

```bash
docker --version
docker compose version
```

两条命令都能显示出版本号就可以。还没装的话，请参考 Docker 官方文档安装：https://docs.docker.com/engine/install/

内存建议 512 MB 以上，磁盘只要放得下程序本身（几百 MB）即可，备份数据不经过本机中转落盘。

## 二、部署（约 3 分钟）

在服务器终端依次执行：

```bash
# 1. 下载项目（先进入你想放项目的目录，这里以 /opt 为例，可换成任意目录；
#    下载完会得到一个 rclona 文件夹，后面的命令都在这个文件夹里执行）
cd /opt
git clone https://github.com/obview/rclona.git
cd rclona

# 2. 准备配置文件
cp .env.example .env
```

用任意文本编辑器打开 `.env`，按需修改（都有中文注释）：

| 配置项 | 说明 | 默认 |
| --- | --- | --- |
| `PANEL_PORT` | 面板网页的端口，被占用就改一个 | `8080` |
| `PANEL_USER` | 面板登录用户名 | `admin` |
| `PANEL_PASSWORD` | 面板登录密码。**留空也可以**，首次打开网页时会引导你设置 | 空 |
| `TZ` | 时区，影响定时备份和自检的时间 | `Asia/Shanghai` |

```bash
# 3. 启动（首次部署要带 --build：先把项目构建成 Docker 镜像，慢一点是正常的）
docker compose up -d --build

# 4. 查看是否启动成功（看到容器状态为 Up 即成功）
docker compose ps
```

然后在浏览器打开 `http://你的服务器IP:8080`：

- 如果 `.env` 里留空了密码，页面会先让你**设置账号和密码**，照着提示走即可；
- 如果 `.env` 里写了密码，直接用它登录。

> 打不开页面？先检查云服务器的**安全组 / 防火墙**是否放行了 8080 端口（或你改的端口）。

## 三、完成第一次备份

### 1. 添加网盘

登录后进入左侧「网盘管理」→「添加网盘」，给网盘起个名字（自己能认出来就行），选择类型后照提示填写。
添加完成后它会自动测试一次连接，结果直接显示在列表里。

**示例 A：Cloudflare R2**

1. 类型选「S3 存储」，服务商选 Cloudflare R2 的预设
2. 填三样东西（都在 Cloudflare 控制台 → R2 →「管理 R2 API 令牌」里创建）：
   - Access Key ID（访问密钥 ID）
   - Secret Access Key（机密访问密钥）
   - Endpoint（接入点）：形如 `https://你的账户ID.r2.cloudflarestorage.com`
3. 保存即可。之后选文件夹时，桶（bucket）会像文件夹一样列出来

**示例 B：Koofr**

1. 先去拿一个「应用专用密码」：登录 [koofr.eu](https://koofr.eu) → 右上角头像 → Settings → Security → App passwords → 生成一个，名字随便填（比如 `rclona`）
2. 回到面板添加网盘，类型选「Koofr」，填你的 Koofr 登录邮箱 + 刚才的应用专用密码
3. 注意：这里要填的是**应用专用密码**，不是你的 Koofr 登录密码

其他网盘（WebDAV、各家 S3、本地目录等）同理，表单会按类型自动列出要填的项，带 `*` 的为必填。看不懂的参数不用慌：每项都有中文说明，点参数旁边的圆圈问号，还会告诉你这个值去服务商的哪里找。

> **网盘可以暂停**：暂时用不上的网盘，在列表里点「暂停」即可。暂停后它不参加每天的连通自检，用到它的备份任务到点会自动跳过（留一条「已跳过」记录，不算失败）；侧边栏里它的状态点会变成灰色。想继续用就点「恢复」。

### 2. 新建备份任务

进入「备份任务」→「新建任务」：

1. 选**源网盘**，再点进去选要备份的文件夹
2. 选**目标网盘**，再选备份存到哪个文件夹
3. （可选）点「再加一组」，一个任务里可以放多组文件夹对，一起按时跑
4. 选**同步方式**：默认「镜像」就行；想让源里删了目标也不删选「单向增加」，两个网盘要互相对齐选「双向同步」
5. 选执行计划：每天、每周（星期可多选）、每月几号、每隔几小时、每隔几天都行；熟悉 cron 的也可以选「高级：cron 表达式」
6. 表单里还有一处「备份加密」开关和一组高级选项（旧版本保留、删除安全阀、限速等），**都可不设**，需要时再开；拿不准的点旁边的圆圈问号有白话说明
7. 保存。任务会出现在列表里，可以随时启用 / 停用 / 删除 / 复制一份；想马上跑一次就点任务上的「立即执行」

> 三个贴心行为，免得你疑惑：
> - **目标文件夹不存在也没关系**：不用提前去目标网盘里建文件夹，执行备份时会自动创建好；
> - **关机错过不用担心**：如果计划时刻到了、但服务当时没在运行（比如服务器关机、断电），服务下次启动后会把错过的这次**补跑一次**；
> - **新建任务不会立刻跑**：新建的任务从**下一个计划时刻**开始执行。想马上验证一次，就点任务上的「立即执行」。

### 3. 先手动跑一次验证

在任务上点「立即执行」，然后去「运行记录」或「概览」看结果：

- 显示**成功**且文件数对得上，就可以放心了，之后它会按时自动跑；
- 显示**失败**也没关系，点开记录会告诉你卡在哪个阶段、是什么原因，照着原因改（比如密码填错了就去网盘管理里改）再跑一次。

## 四、备份服务器上的文件（可选）

除了网盘之间互备，rclona 也能备份**这台服务器上的文件**（比如网站文件、各种配置），备到 Koofr、R2 等网盘里。
原理是给容器开一扇只读的「窗」：让面板能**看到**服务器的整个硬盘，但只能读、不能改——备份只会读你的文件，动不了源文件，放心。

开启只需要三步：

1. 打开部署目录里的 `docker-compose.yml`，找到 `volumes:` 下面那行被注释掉的挂载（写着 `# - /:/host:ro`），把行首的 `# ` 删掉；
2. 在部署目录执行 `docker compose up -d` 重建容器（配置变了它会自动重建，数据不会丢）；
3. 回到面板：「网盘管理」里添加一个**本地目录**网盘（什么参数都不用填），再建备份任务、选文件夹时**从 /host 进去**——/host 里就是服务器的全部文件，挑你要备的目录，目标选你的网盘，保存即可。

**哪些目录值得备？** 参考清单（在选文件夹时对应 /host 下面的路径）：

| 目录 | 这是什么 |
| --- | --- |
| `/host/etc` | 系统与各软件的配置文件（体积小，但很关键） |
| `/host/root` | root 用户的家目录，常放脚本、部署文件 |
| `/host/home` | 普通用户的家目录 |
| `/host/opt` | 很多人把自己装的程序、项目放在这里 |
| `/host/var/www` | 网站文件（如果你的网站放在这里） |
| `/host/var/lib/docker/volumes` | Docker 容器们的数据卷，其他服务的数据多半在这里 |

> - 直接把整个 `/host` 当源也行：`proc`、`sys`、`dev`、`run` 这些系统虚拟目录会被**自动跳过**（执行记录的日志里会注明）。但更推荐按上表挑重要目录分别建任务：文件少、跑得快、将来恢复时也好找。
> - 再强调一次：这是**文件级备份**，保的是「数据不丢」；它**不能**把一台坏掉的服务器一键还原成能开机的样子。
> - 开启后，能登录面板的人就能浏览服务器上的全部文件——面板密码务必设强一点（见「七、安全建议」）。

## 五、开启 Telegram 通知（推荐）

备份失败、网盘连不上（以及恢复正常）时，让一个 Telegram 机器人第一时间把消息发给你——消息里写明了失败在哪个阶段、是什么原因。

进入「设置」页，打开 Telegram 通知开关，按这三步填：

1. **建机器人拿令牌**：打开 Telegram，搜索 **@BotFather**，给它发送 `/newbot`，按提示给机器人起个名字，它会回你一串**令牌（Bot Token）**，复制下来
2. **给机器人打个招呼**：打开你刚建的机器人，随便给它发一句话（不先发消息，它没法主动找你）
3. **拿你的 Chat ID**：在 Telegram 里搜索 **@userinfobot**，它会回你的数字 ID，把这串数字填到设置里的 **Chat ID**

把令牌和 Chat ID 填进设置页，点「先存并发送测试通知」——Telegram 里收到测试消息就配好了。设置页每个输入框旁边都有圆圈问号，点开有更细的图文步骤说明。

**顺手再填一项（可选）：面板访问地址。** 在设置页的「面板访问地址」里，填上你平时打开面板用的地址（比如 `https://panel.example.com`，或 `http://服务器IP:8080`）。填好后，备份失败的通知末尾会带一条链接，点一下就直接跳到出错的那条记录，不用自己再去翻。**填错了也不怕**：最多就是那条链接打不开，通知本身照常发送，回来把地址改对就行。不想填就留空，通知只发文字。

## 六、日常维护

都在项目目录（`rclona` 文件夹）里执行：

```bash
docker compose logs -f      # 看运行日志（Ctrl+C 退出，不影响运行）
docker compose restart      # 重启
docker compose down         # 停止并删除容器（数据保留）
docker compose up -d        # 再次启动
```

**更新到新版本**：

```bash
git pull
docker compose up -d --build
```

**备份 / 迁移数据**：两种办法任选——

- **面板里导出（推荐）**：「设置」页有「导出配置」，下载到的是一份**完整备份文件**（网盘凭证、任务、通知设置、连面板账号都包含）。换新机器装好 rclona 后，在设置页「导入配置」选这份文件，确认后全部原样还原，不用再补填任何密码。
  ⚠️ 这份文件等于你所有网盘的钥匙：只许放在自己的设备上，不要发给任何人、不要传聊天软件、不要放公开网盘。
- **打包数据卷**：所有数据（网盘配置、任务、记录、设置）都在 Docker 数据卷 `rclona-data` 里，迁移时把这个卷打包带走也可以：

```bash
docker run --rm -v rclona-data:/data -v "$PWD":/backup alpine tar czf /backup/rclona-data.tar.gz -C /data .
```

**彻底卸载**：

```bash
docker compose down -v      # 连数据卷一起删，网盘配置和记录都会清空
```

**修改面板端口**：改 `.env` 里的 `PANEL_PORT`，然后 `docker compose up -d` 重新启动。

## 七、安全建议

- 面板里存着你各个网盘的钥匙，**请设置一个强密码**，不要用默认口令
- **不建议把面板端口直接暴露在公网**。更稳妥的做法（任选其一）：
  - 只在局域网 / 内网使用；
  - 用 Cloudflare Tunnel 把面板绑到自己的域名上（自带 HTTPS，且不用开放任何端口）；
  - 用 Nginx 等反向代理加 HTTPS 后再对外
- 网盘的访问密钥建议按最小权限创建（比如 R2 令牌只授权要备份的那一个桶、只给读写）

## 八、常见问题

**Q：备份为什么失败？**
A：去「运行记录」点开那条失败记录，会显示卡在哪个阶段和白话原因（如「密码或密钥不正确」「连接不上」「目标空间不足」「路径不存在」），按原因处理即可。还能展开看原始日志摘要。

**Q：Telegram 通知里的链接点不开？**
A：多半是设置里的「面板访问地址」没填或填错了（比如换了域名 / IP 没跟着改）。把它改成你现在实际打开面板用的地址即可；不填这个地址时，通知只发文字、不带链接。

**Q：想备份服务器上的文件怎么办？**
A：见「四、备份服务器上的文件」：开启只读挂载后，添加一个本地目录网盘，建任务时从 /host 里挑目录备份即可。

**Q：目标网盘里的文件被删了，是出 bug 了吗？**
A：不是。这就是「纯镜像」的行为：目标与源保持完全一致，源里没有的文件目标里也不会留。详见文首的警告。

**Q：定时的时间对不上 / 自检不在凌晨 3 点？**
A：检查 `.env` 里的 `TZ` 时区是否为 `Asia/Shanghai`，改完重启容器生效。

**Q：忘记面板密码怎么办？**
A：如果密码是在 `.env` 里设置的，改 `.env` 后重启即可。如果是在首次打开网页时通过向导设置的，密码保存在数据卷中，重置需要清空数据卷（`docker compose down -v` 后重新部署），网盘和任务配置会一并丢失、需要重新添加——所以请务必记好密码。

**Q：网盘显示「连接失效」怎么办？**
A：多半是密码 / 密钥被改动或过期，或网盘服务商那边出了故障。到「网盘管理」里核对配置、重新测试；服务恢复后自检会自动把它变回正常。

**Q：支持哪些网盘？**
A：rclone 支持的都可以添加，常用的有 S3 协议存储（Cloudflare R2、AWS S3、七牛、阿里云 OSS 等）、Koofr、WebDAV（坚果云、Nextcloud 等）、本地目录。少数需要网页授权登录的网盘（如 Google Drive）配置较复杂，建议查阅 rclone 官方文档获取令牌后填入。

## 架构（给好奇的你）

单个 Docker 容器里跑三部分：

| 组件 | 说明 |
| --- | --- |
| 前端 | Vite + React 构建的网页，网关直接托管 |
| 网关 | Node 服务：登录鉴权、任务调度、五阶段执行、运行记录、网盘自检、Telegram 通知 |
| rclone | 以 `rcd` 模式运行，网关通过它的 HTTP 接口执行实际同步 |

数据全部存放在单一数据卷 `/data`，方便备份和迁移。

## 本地开发

```bash
cd frontend && npm install && npm run dev    # 前端开发服务器
cd gateway  && npm install && npm start      # 网关（需本机有 rclone 二进制）
cd gateway  && npm run test:e2e              # 端到端自测
```
